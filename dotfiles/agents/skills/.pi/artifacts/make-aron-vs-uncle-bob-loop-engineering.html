What v1 got wrong

v1 analysed make-aron as if the worker step was a black box. It isn't — make-aron/SKILL.md:102-106 hands every ticket to ship, and ship is where the engineering pipeline lives. Four v1 claims retract:

v1 claim Verdict Reality
D4 nothing ever reduces complexity wrong playbooks/simplify/ is a cleaner. Runs twice per feature: Phase 7b (ALWAYS) + post-step.
D5 test quality never measured wrong subagents/reviewer-test-quality.md is a hardener. Detectors A–F target exactly the mutation-testing bug class.
D11 no inner loop wrong Per-file typecheck loops in add-observability, harden-types, add-empty-error-states; per-fix test loop in simplify, audit.
D2 zero project-invariant deterministic gates wrong add-feature/PLAYBOOK.md:342 "Final candidate gate — AFTER every mutation" is fixed, identical every run, and self-recursive.

Restated correctly, the stack is:

  • make-aron = Bob's outer orchestration (which task, in what order, who writes, when to commit). Bob barely has this.
  • ship = Bob's inner gauntlet (coder + cleaner + hardener + QA).
  • Combined, 4 of Bob's 5 phases exist. The gap is not phases — it's mechanism.

The one difference that survives

Every quality judgment in your stack is an LLM reading code. Bob's are arithmetic.

Not a single number is computed anywhere in make-aron or ship: no cyclomatic complexity, no coverage percentage, no CRAP score, no mutation score. The closest thing is simplify/references/code-smells.md:12 — "files >300 lines or functions >50 lines that have natural seams. A cohesive 400-line file is fine; an incoherent 200-line file is not."

That sentence is precisely what Bob's whole talk is about. It is a threshold that an agent argues with. lizard --csv | crap.py --threshold 6 is a threshold that exits 1.

Everything below is a consequence of that one difference.

Remaining differences

Mechanism

D1. Prose thresholds vs computed thresholds. ship names the same smells Bob's cleaner targets — nested conditionals 3+ deep, long functions, tight coupling — but every one is judged, and each carries an explicit escape hatch ("A cohesive 400-line file is fine", "NEVER split a file just because it's long"). Bob's counter-position: with 100% coverage CRAP = comp, "a crap score of six means there are six pathways through the function" — no judgment, no escape hatch, no negotiation. Your escape hatches are well-reasoned (they defend against Bob's own documented function-shredding failure mode). They are also unfalsifiable.

D2. reviewer-test-quality is a reader; mutation is a generator. Detectors A–F are the best LLM approximation of a hardener I've seen — Detector C ("changed lines never executed") is coverage-by-reasoning, Detector F ("defining invariant unasserted") is arguably stronger than mutation testing, since mutation cannot tell you a stated business rule went unasserted. But the technique gap is real: a reader checks the assertions it thinks to check. A mutator enumerates the operator space — every <→<=, every &&→||, every deleted call — and reports survivors exhaustively. Bob shelved mutation testing for 20 years because reading tests doesn't find what mutating them finds. No mutation score exists, so no threshold, so nothing to gate.

D3. Inner loop is discipline, not a hook. add-observability/PLAYBOOK.md:75 — "After each file, run type-check … Do not bulk-edit then verify at the end." Correct instruction, same intent as Bob's PostToolUse. Difference: a hook fires whether or not the agent remembers. This is exactly the steering/constraining split, applied to the cheapest layer. Adding the hook costs an hour and makes the prose rule redundant.

D4. No architecture enforcement. Bob: a dependency specification file + deterministic checker; violation → invert the dependency, insert an interface, or split the module. Non-negotiable. Your stack: audit/PLAYBOOK.md:39 records architecture smells (circular deps, cross-layer imports) as findings during a whole-repo sweep; reviewer-dependencies is supply-chain (npm audit, install scripts, licenses), not module layering. make-plan-aron writes architecture docs to ./docs/, never checked afterward. Net: nothing prevents ticket T7 introducing a banned dependency, and both impl-worker (Stay inside the ticket … drop) and global D6 tell the worker to log it as residual risk rather than fix it. This is the largest phase-level gap left.

D5. No project-level CI/nightly layer. AgentSystemLabs/core has real CI on itself — scripts/check-skill-routing.mjs lints that every reviewer declares the severity scale and an auto-fixable field (findings-contract.md:7). That is Bob's "constrain, don't steer" applied one level up, and it's the most Bob-like thing in the whole stack. None of it points at your project. make-aron ends at git push -u origin HEAD, PR: no unless asked. No trend, no number that can't be bypassed, nothing that outlives the run.

D6. No determinism prerequisite. Bob: pin the clock, seed the PRNG, TZ=UTC, isolate DB state — before the hardener, because a flaky suite makes a random failure read as a kill and a random pass read as a survivor. Nothing in either layer requires a deterministic suite. Blocks adopting D2.

Structure

D7. Planning weight — still a direct contradiction, now with an ally on both sides. Bob: heavy up-front spec = waterfall = "always a disaster"; agents love writing gorgeous plans that fall apart; do a story or two, look at the architecture, intervene manually, do a few more. make-aron: full ticket DAG + mermaid + HTML plan + ADRs up front, then "Never re-open the plan for approval. No mid-run check-in." ship sides with you on one half — add-feature Phase 4 is a mandatory plan-approval gate and plan-red-team adversarially challenges production plans before approval. It sides with Bob on the other half: those gates exist to let a human look mid-flight, which make-aron then suppresses (see F3). Also note the agreement Bob would like: your plan artifacts are deleted at End cleanup. He says specs are ephemeral; you implement that literally.

D8. Cleaner/hardener ordering — Bob's rule half-followed. Bob: cleaner first, hardener second, always, because their trajectories oppose. ship: simplify at 7b → tests at 8 → reviewer-test-quality → simplify again as post-step → final gate. The tail runs the cleaner after the hardener, re-entering the "reduce branching" trajectory on top of freshly-strengthened tests. Mostly defused by the final gate's add-feature/PLAYBOOK.md:349 — "If any final-gate fix changes code, repeat this gate from step 1. A fix is not allowed to certify itself." Worth knowing you diverge, not worth changing.

D9. Two ledgers per run. ship writes <session-scratch>/agentsystem/runs/<run-id>.md — durable control plane, survives compaction, base-SHA validated before trust. make-aron writes ./.tmp/MAKE_PROGRESS_{slug}.md — ticket state truth. Neither knows about the other. The parent reads worker reports, not ship ledgers, so ship's per-phase evidence is compressed to one Ship terminal: line and then discarded. Bob has neither; this is a place your stack is ahead of him and is throwing away the advantage.

D10. Two incompatible severity vocabularies. findings-contract.md is a declared pack-wide API — CRITICAL/HIGH/MEDIUM/LOW + auto-fixable: true|false, CI-linted, consumed mechanically by the parent playbook. roles/reviewer.md uses blocker | should-fix | note, and only blocker earns a fix pass. Both run in one make-aron job — ship's reviewers inside each worker, yours on the final diff. Nothing maps HIGH onto blocker. Nothing merges the two finding sets.

D11. Evidence, measured vs asserted.

  • ship: benchmarked. 5 briefs × 3 arms on a real Laravel/Inertia/React app, blind-graded by a stronger model: 47.0/50 vs 43.2 plain / 41.0 persona, 5/5 features won, 0 crashes vs 2 crash classes, invariant tests in 5/5 vs 1/10 raw branches, +81% tokens. Limitations documented (n=5, LLM judge, conflict of interest).
  • Bob: 4–5× productivity, self-reported, no data, and he says himself he debated the CRAP threshold with the agents and "you can't trust a debate with an agent."
  • make-aron's own additions (deep planning, ticket DAG, Opus-5-xhigh-everywhere, reviewer fanout): unmeasured. You inherited a benchmarked engine and wrapped it in an unbenchmarked orchestrator.

D12. Cost lever. Bob: cheap agents + expensive deterministic rechecks, ~1h/task. You: ship costs +81% tokens over plain prompting, and make-aron stacks Opus 5 xhigh on every ticket plus deep planning plus deep reviewer fanout on top of that. Same total budget, spent on model capability rather than on tools. His side of the trade is the one that doesn't regress when the model changes.

Defects found

F1. make-aron never passes headless=true — and its workers are subagents. ship/SKILL.md:81 defines headless=true as the sanctioned way to run without user interaction: "Headless removes user interaction, NOT rigor — it skips QUESTIONS, never QUALITY gates." It auto-resolves the production confirm, forwards to the playbook, converts Phase 4 approval to log-and-proceed, and records every assumption. make-aron instead does this (SKILL.md:127): "Any implementation special action/tool confirmation → auto-approve inside this skill. Includes production ship confirmation." — against ship/SKILL.md NEVER: "NEVER bypass a routed core skill's own approval gate." Concrete failure: the worker is a subagent. ship mandates AskUserQuestion at Phase 4, the mode-conflict prompt, and intent disambiguation. A subagent calling AskUserQuestion cannot reach the user. So every production-mode ticket either stalls or the model improvises past a gate that was designed to be converted, not skipped — and the assumptions headless would have logged are lost. Fix is one word: add headless=true to the ship invocation in make-aron/SKILL.md:102-106. grep -n headless make-aron/SKILL.md → no match.

F2. Tier contradiction, make-aron vs impl-worker. orchestration.md and roles/impl-worker.md say worker default standard, and "Tier: deep in your prompt → risky surface or a repair after failure". make-aron overrides to "Opus 5, effort xhigh, always". Legal (caller wins), but every worker now reads a role file whose explanation of its own tier is false, and the escalation row admits it buys no model change.

F3. Branch name conflict. plan/{slug} in Auto-decide + Git rules; feat/{slug} in Pre-flight step 3. Same file.

F4. Severity vocabularies unmapped (D10). Ship findings the worker chose not to auto-fix surface in its report as prose; your parent's blocker-only fix pass has no rule for consuming them.

F5. Ship's ledger is discarded (D9). Per-phase evidence, reviewer coverage, and finding dispositions exist in a structured file the parent never reads.

Revised adoptions — cheapest first

  • X1. Add headless=true (F1). One word. Fixes a live gate-bypass, not a nice-to-have. Do this first.
  • X2. PostToolUse hook for lint+typecheck (D3). Hours. Converts ship's most-repeated prose rule into something that can't be forgotten. Highest ratio in the list.
  • X3. Map CRITICAL/HIGH → blocker (D10/F4), and have the parent read the ship run-ledger path from the worker report (F5). Small, closes two leaks.
  • X4. CRAP script as a ship gate (D1). ~40 lines of Python + lizard + lcov. Run it inside simplify Phase 5 alongside the existing typecheck, threshold 6. Keeps ship's escape hatches for the prose smells while making one dimension non-negotiable.
  • X5. Dependency-rule checker (D4). Emit a machine-readable layer spec from make-plan-aron's architecture step; check it in make-aron's final validation. The only fully-missing Bob phase.
  • X6. Mutation on the diff (D2). Highest value, highest cost, gated on D6 (pin clock/PRNG/TZ first). cargo-mutants --in-diff / stryker --since=main. Feed the score to reviewer-test-quality as input rather than replacing it — its Detector F catches something mutation can't.
  • X7. Benchmark your wrapper (D11). ship shipped a 3-arm benchmark with its own limitations section. Run make-aron-over-ship vs bare ship on the same briefs, or you're asserting the same way Bob does.
  • X8. Reconsider the one-way autonomy boundary (D7). Policy, not tooling. You now have two independent sources — Bob's "always a disaster" and ship's mandatory Phase 4 gate + plan-red-team — arguing that the mid-flight human look is load-bearing. Deliberate disagreement is fine; unexamined isn't.
