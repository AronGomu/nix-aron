3. The rule set worth building

Units (fix these first, everything else hangs off them)

word            whisperx, ~10 ms
chunk           words separated by a pause ≥ 0.30s
take            words between two backward jumps in the script alignment
script sentence the unit a viewer perceives as "one line"

Today the tool reasons in takes. Takes are too coarse (a 361-word take covered a third of the script) and too fragile (one bad jump changes everything). Move the invariant to script sentences.

The one invariant

For each script sentence S, keep exactly one delivery: the last one that covers at least X% of S's tokens (default 70%). Every earlier delivery of S dies, truncated at the word where the surviving delivery starts.

Everything below is either a way of finding deliveries, or an exception to that invariant.

Rules, ordered by confidence

id Rule Signal Default
R1 verbatim restart exact repeat of ≥2 normalised words, adjacent cut first copy, auto
R2 script regression backward jump in DP alignment cut earlier take from the restart word, auto
R3 incomplete delivery chunk covers <70% of sentence S, a later chunk covers more of S cut the partial, auto
R4 reworded restart two deliveries of S with high script-coverage overlap but low text similarity candidate, review
R5 off-script duplicate adjacent chunks, no script anchor, embedding cosine ≥ 0.85 (multilingual sentence model) candidate, review
R6 filler head chunk starts with euh/ben/alors euh/donc euh then a pause trim tokens, auto
R7 abandon marker on refait / je reprends / merde / putain + laugh cut back to start of current sentence, auto
R8 acoustic repeat net mel self-similarity stripe ≥1.2s at 0.8–40s lag, no matching text pair candidate, catches what the ASR collapsed

R1/R2/R6 exist today (R1 as --stutter-words, R2 as the DP, R6 not at all). R3/R4 are the highest-value additions: they replace the text-similarity guard, which is the thing currently rejecting real retakes (6 rejections logged in full_plan.json under rejected, each with its reason).

Guards, so it never eats good takes

  • a delivery may only be superseded by a later, more complete one (never by a shorter fragment)
  • a take still running when the analysed window ends supersedes nothing (already in)
  • never cut across a sentence the script does not contain — improvisation is protected unless R5 fires
  • every cut boundary stays in silence between two words (already in)

4. How to build the rule set, not guess it

The rules are cheap; the thresholds are the product. Loop:

  1. Recall-first pass — run plan with loose thresholds, emit candidates.json = drops plus near-misses, each tagged with the rule id and the reason it fired or didn't. (rejected[] already exists; needs the rule tag.)
  2. Review page — single HTML with the source video, one row per candidate: text of the dropped span, text of the survivor, timestamps, ▶ button seeking the video, and keep/cut buttons. Export decisions.json.
  3. Regression set — your decisions become labels. retake-cut eval decisions.json reports precision/recall per rule and sweeps each threshold, so a change is measurable instead of vibes.
  4. Ship thresholds in ~/.config/retake-cut.conf (same shape as remove-silence.conf), re-render without re-transcribing.

After ~2 videos of labels, the thresholds stop being my guesses and start being your editing taste, and R4/R5 can graduate from "candidate" to auto.

5. Order I'd implement it

  1. sentence units + the one invariant (R3) — biggest recall win, no new dependency
  2. R4 on script coverage instead of text similarity — recovers the 6 logged rejections
  3. review page + decisions.json — turns the rest into data
  4. R6/R7 filler + abandon markers — cheap, visible polish
  5. R5 embeddings and R8 acoustic net — only if labels show they are needed
